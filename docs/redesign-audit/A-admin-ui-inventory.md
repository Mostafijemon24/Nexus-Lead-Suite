# Nexus Lead Suite — Admin SPA Functional Inventory (from shipped bundle)

Source of truth: `assets/admin/js/main.js` (beautified copy: `scratchpad/bundle/main.beautified.js`, app code begins at line 8781 after React/ReactDOM/lucide vendor code). All line numbers below refer to the beautified file. Minified identifiers are quoted in parentheses (e.g. `lx`) so a redesign can map components back to the bundle.

Conventions used in this document:
- **REST** = `fetch()` against `window.nexulesuite_Admin.restUrl + "nexulesuite_/v1/..."`, always with header `X-WP-Nonce: nexulesuite_Admin.nonce`; `credentials: "same-origin"` where stated.
- `tu()` (line 19305) is the shared REST helper: `tu(path, opts)` → `fetch(restUrl.replace(/\/$/,"") + path, { credentials:"same-origin", headers:{ "Content-Type":"application/json", "X-WP-Nonce": nonce, ...opts.headers }, ...opts })`, throws `Error(json.message || "Request failed")` on `!res.ok`, returns parsed JSON.
- `Pi()` (9497) / `Mi()` (10731) return `{restUrl, nonce[, siteTitle]}` from `window.nexulesuite_Admin`.
- "UNVERIFIED" = the UI sends a request but I could not confirm the PHP route exists/handles the payload from the bundle alone.

## 12. Accessibility & keyboard summary (cross-page)
- Landmarks: `<aside aria-label="Nexus Lead Suite navigation">`, `<nav id=… aria-labelledby>` with `sr-only` `<h2>Main menu</h2>`, `<header>` with `<nav aria-label="Breadcrumb">`, `<main>`; page frames use `<h1>` titles; sections mostly use `<span>`/`<p>` for titles (not headings) inside `nexulesuite_*-sec-title`; some `<h2>/<h3>/<h4>` in Smart Buttons, Popups, Forms, Submissions.
- Modals: `gd` (result/confirm), Activities Report, Smart Buttons Quick Preview declare `role="dialog" aria-modal="true"`; **only the Activities Report modal handles Escape**; Field picker, Form Preview, Add-a-Form, Pop-Up Simulator, Email HTML editor / Render Preview have no dialog role. **No modal implements a focus trap or returns focus**; only the field picker search and Submissions search use `autoFocus`.
- Switches: consistent `role="switch" aria-checked` (`Ha`, `nexulesuite_sg-toggle`, `nexulesuite_gd-toggle`, `nlsVeToggle`, form "Show form on website"); `nexulesuite_gd-toggle` and `nexulesuite_gd-cond-top` support Space/Enter via `tabIndex=0`.
- Tablists: `role="tablist"/"tab"/"aria-selected"` used for match-mode, edit-mode, text-alignment segments and Acc&Lang offset/display tabs; Analytics tabs, Settings tabs, Form multi-step tabs, AI sub-tabs are plain buttons.
- Menubar (Submissions) uses `role=menubar/menuitem/menu`, `aria-haspopup`, Escape + outside click close.
- Icon-only buttons: many have `aria-label` (close, delete, drag, remove, copy), but Form card header actions, Smart Buttons row actions (Duplicate/Delete/Quick Preview) and Popups Delete rely on `title` or have none.
- Keyboard shortcuts: none custom; ⌘K is WP core command palette. Sidebar search clears on Escape. Email recipients add on Enter/comma. AI logs search submits on Enter.
- No `aria-live` regions and no `role="alert"`: all save/error feedback is via modal (`Ua`) or inline text, so screen readers get no announcement for inline "Saved."/"Updating…" states.
- Polling/intervals: none (`setInterval` unused). Timers only for debounces (300–400 ms), copied-state resets (1.5–2 s) and TinyMCE readiness polling.
