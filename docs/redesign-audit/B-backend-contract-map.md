## 2. REST routes (all 54 registrations)

Response envelope convention: most handlers return `{ success: true, data: {...} }` via `rest_ensure_response`. Exceptions are noted. `WP_Error` without a `status` arg is emitted by core as HTTP 500.

#### POST `/render-shortcode` → `render_shortcode_preview` (5703)
- Perm: `can_manage_settings`.
- Args: `content` (string, required). Handler also falls back to JSON body `content`. ## 7. HIGH RISK for a presentation-layer redesign

1. **PHP inline script that queries the admin DOM** — `admin/class-admin-app.php` line 378 (`wp_add_inline_script('nexulesuite_admin', …, 'after')`): scans every `<select>` whose first `<option>` text contains "select a popup", inside the closest `div.p-5` whose `<label>` text contains "button 01", and appends a disabled `— Forms —` separator plus one `<option value="form:{id}">` per form from `window.nexulesuite_Admin.formsPayload.forms`; uses a `MutationObserver` on `document.documentElement`. If the redesign changes the Tailwind wrapper class (`p-5`), the label text, the placeholder option text, or stops using a native `<select>`, the "Button 01 → form" feature silently disappears. The backend expects the resulting stored value `popup:form:{formId}` in `GS.chatFormButtonLink` (handled in `build_livechat_parts`). Recommended: have the new UI add the form options itself and keep emitting `popup:form:{id}`. This is the ONLY DOM-querying inline script in admin PHP (verified by grep: only `admin/class-admin-app.php` and `public/class-shortcodes.php` contain `querySelector`/`getElementById`/`MutationObserver`).
2. **`window.fetch` monkey-patch for email templates** — `append_email_templates_rest_patch` (same file, line 596, injected `before` the admin script): rewrites any fetch whose URL contains `emails/templates` to `{restUrl}nexulesuite_/v1/emails/templates` and base64-encodes `templates[].content` with `contentEncoding:'base64'`. A redesign that uses XHR/axios, a different URL, or already encodes will bypass or double-apply this. Server accepts both raw and base64 content, so the main risk is WAF false positives on raw HTML bodies (the reason the patch exists).
3. **Settings payload sparse-vs-full semantics** (`save_general_settings`, §2.1): several keys reset to defaults when omitted (`enableNavigation`, `allowClientAccess`, `enableAutoPopup`, `globalFont`, `tokenTTL`, `clientAccessSlug`, `reportLogo`, `reportLogoPdfMax`, `excludePosts/Pages`, `activityButtonClasses`, `selectedEmailTemplate`, all `form*` keys, `autoPopupFormIds`). A tabbed UI that POSTs only the visible tab's keys will silently wipe the others. Conversely `aiFaq*/aiActions/aiLead*/aiWooCards/aiExtraUrls/aiContactShortcode/aiExamples` in this payload are ignored (must use `/ai/faq`). `/ai/faq` POST treats missing booleans as false.
4. **Secrets are write-only**: `aiApiKey`, `aiLlmApiKey`, `aiEmbedApiKey`, SMTP `password`, `oauth_client_secret`, reCAPTCHA `secretKey` — blank means "keep", GET returns only `has*`/`secretMasked`/`hasPassword` flags. Turnstile `secretKey` is the exception: blank overwrites with ''. Switching `aiLlmProvider`/`aiEmbedProvider` without a new key clears the stored key.
5. **Stored numeric strings**: `GS.tokenTTL/chatPadding/chatBorderRadius`, menu item `style.paddingVertical/paddingHorizontal/radius`, popup `style.*` sizes and `logic[].delay/scrollPercentage` are returned as strings; `GS.form*` sizes and `globalFontSize` as ints. Equality checks / controlled inputs must tolerate this.
6. **Response envelope inconsistencies** the UI must keep handling: `/settings/accessibility-language` GET returns `{settings, catalog}` (no `success`), POST returns `{success, settings}`; `/smtp/test` returns `{success, note}`; `/smtp/oauth/start` returns `{success, url}`; `/ai/test`, `/ai/train`, `/ai/reset`, `/ai/autogen`, `/ai/chat` report failures as HTTP 200 `{success:false, message}`; `/reports/activities/list` section denial is a 403 `WP_REST_Response` with `code` in the body; many `WP_Error`s omit `status` (HTTP 500 with `{code, message, data:null}`).
7. **OAuth return trip into the SPA**: after Gmail/Outlook consent the browser lands on `admin.php?page=nexus-lead-suite-settings&nls_smtp=connected|disconnected|error&nls_smtp_msg=…`. The redesigned Settings page must read and surface these query args (and route to the SMTP tab). `authorize_urls`/`disconnect_url` in the SMTP payload are admin-post nonce URLs; the REST `/smtp/oauth/start` exists because those nonces go stale.
8. **Admin page/route coupling**: `initialRoute` is derived from `?page=` (map in §5); `adminPages` provides sidebar URLs; WP submenu order is forced in `reorder_submenu`; hidden pages `-forms/-templates/-submissions` must keep existing for bookmarks. The mount node id `nexulesuite_admin-root`, script handle `nexulesuite_admin` (translations bound to it), manifest entry `src/main.jsx`, and CSS handle `nexulesuite_admin-0` (dependency of the FUI/range-slider styles) are fixed contracts. Admin font rules only apply inside an element with class `nexulesuite_admin-app`.
9. **Popup Simulator** relies on `admin-ajax nexulesuite_popup_preview` (not REST) so Forminator renders; the response `headHtml/footerHtml` contain raw `<link>/<script>` tags meant for an iframe. `/render-shortcode` is the REST twin with the same payload.
10. **Front-end markup/ids are a JS contract**: the livechat inline JS binds to ~45 fixed ids (`nexulesuite_chat-trigger`, `-panel`, `-close`, `-form-view`, `-form-back`, `-leadgate-*`, `-ai-view`, `-ai-*`, …) and classes (`.nexulesuite_chat-panel__head`, `.nexulesuite_chat-inline.is-bleed`, `[data-nexulesuite_chat-popup]`, `[data-nexulesuite_chat-open-form]`, `[data-nexulesuite_chat-open-ai]`); popups rely on `.nexulesuite_popup-overlay[data-event][data-logic]`, `.nexulesuite_popup__close`, `.nexulesuite_st-form`, `.nexulesuite_st-form-result-card`; the bridge/tracker rely on `data-nexulesuite_trigger="{event},{label}"`, `popup:` hrefs and the class maps from `activityButtonClasses`; forms rely on the `.nexulesuite_st-*` structure, `data-nexulesuite_ajax`, hidden `nexulesuite_form_id`, nonce `nexulesuite_form_nonce`, honeypot `nexulesuite_hp_website`, captcha response field names. `wp_kses(allowed_embed_html()/allowed_form_html())` strips any new attribute/tag not in those allowlists (core/popup-shortcode-expand.php) — new `data-*`/`aria-*` attributes in front-end markup will be removed unless added there.
11. **Settings shapes that must stay byte-compatible**: forms payload (incl. `kind:'layout'` nesting, `confirmations[0].isDefault`, `emailRoutes`, `styling` keys), popups (`logic`, `conditions`, `headingEditMode`), menu groups (`conditions.rules[].type` set, `url` `popup:` scheme, `eventName` auto-sync), a11y (`dockButtonOrder/Conditions/Offsets`), email templates (`uuid` must be preserved on round-trip; `content` is kses-filtered — `<style>` blocks are removed on save, so a visual template editor cannot persist stylesheet blocks), client links (`sections` subset of `summary|forms|chats|activities`).
12. **GET with side effects**: `/forms` GET may rewrite the forms option (repair); `/settings/full-export` raises memory/time limits; `Client_Access::resolve_link` sweeps expired links on read; PDF/email routes write files into uploads and leave temp logo JPEGs behind.
13. **Public endpoints need two nonces for logged-in users** (`nexulesuite_track`/`nexulesuite_ai` body nonce + `X-WP-Nonce: wp_rest` header). Any new front-end must send both.
14. **Undeclared params**: `/form-submissions` (`from,to,search,limit`), `/form-submissions/delete` (`ids|id`), `/captcha/recaptcha` POST (`apiVersion`, `scoreThreshold`), `/ai/chat` (`file`, `session_id`, `page_url`) are read from the request without `args` registration — they work but will not appear in schema/OPTIONS discovery.
15. Hard-coded copy the UI must keep in sync: default confirmation / `thankYouMessage` medical-themed text (duplicated in `sanitize_forms_payload`, `handle_form_submit_ajax`, and the `nexulesuite_Forms` localization), livechat button fallbacks ("Start Conversation", "What's App", "E-mail"), admin-only notices.
